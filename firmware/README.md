# Firmware: ESP32-S3-DevKitC-1 (N16R8) AQI node

Three PlatformIO projects. Open one folder at a time in VS Code with the PlatformIO extension. The USB cable goes in the board's **UART** USB-C port, not the native USB port.

| Folder | What it is | Build (2026-11-03) |
|---|---|---|
| `bench_bringup/` | Bench test firmware with one `#define` test mode per module (SD, RTC, LCD, INA219, PMS5003), plus `SETUP_NOTES.md` with every bench lesson | Used to verify each module on its own |
| `data_logger/` | Stage 1: PMS5003 + DHT22 + DS1307, a CSV row on the microSD card every 3 s (`/aqilog.csv`), PM2.5, time, temperature and humidity on the LCD. Survives a lost clock (uptime stamps), a lost card (rows wait in RAM, card remounted) and a lost LCD (re-initialised); prints an I²C roll call and a bus verdict | Bench-proven 2026-11-01/02; SD writes reworked 2026-11-03: 389 KB flash, 45 % static RAM |
| `aqi_classifier/` | Stage 2: the same node behaviour split into modules, plus INT8 TensorFlow Lite Micro inference every 3 s. LCD shows PM2.5, time, AQI class and confidence; the CSV row (`/aqicls.csv`) adds class, confidence, latency, bus voltage and current | Bench-run 2026-11-03: 455 KB flash, 44.6 % static RAM (115 KB of it is the RAM row buffer); bit-identical to the laptop on 15,043 vectors, 0.18 ms per inference |

TensorFlow Lite Micro and the model add about 66 KB of flash over the logger. The interpreter registers only the four ops the MLP uses (QUANTIZE, FULLY_CONNECTED, SOFTMAX, DEQUANTIZE); with the full `AllOpsResolver` the build was 629 KB. That delta is the figure the report's 500 KB flash target refers to.

## Build flags (`aqi_classifier/platformio.ini`)

- `-DTFLITE_SINGLE_ROUNDING=1` makes the TFLM integer kernels round like TensorFlow 2.21's reference kernels. Without it, about 1,400 of 21,282 test rows got different probabilities on the board and 2 changed class.
- `-ffp-contract=off` keeps float32 pre-processing free of fused multiply-adds, so it rounds exactly like numpy.
- These flags also apply to the library. Run `pio run -t clean` after changing them.

`code/08_on_device/host_tflm/` builds the board's own TFLM sources on the laptop with the same flags. Its test shows bit-identical inputs and probabilities to the laptop reference on every test row.

## Patched SD driver (`lib/SD` in both projects)

The framework's SD driver compared the card's data-response token with the wrong values. A block the card rejected for a CRC error, or a busy timeout, was reported as written. Both projects carry a patched copy in `lib/SD`, which PlatformIO prefers over the built-in library; `lib/README.md` documents the change. On top of that, both stages append through POSIX `fopen`/`fflush`/`fsync`. A row leaves the RAM buffer only after those calls succeed and the file grew by exactly the bytes written.

## Model header (`aqi_classifier/aqi_model.h`)

Generated by `code/04_tinyml_model/requantize_int8.py` or `train_mlp.py`, never edited by hand. It holds:

- `aqi_model[]`, a `const`, 16-byte-aligned copy of `models/mlp_int8.tflite`. It stays in flash and TFLM reads it in place.
- `AQI_INPUT_MEAN[4]` and `AQI_INPUT_INV_SCALE[4]`. The firmware computes the model input as `u = (raw - mean) * inv_scale`. This maps each feature's training range onto [-1, 1]. Since 2026-11-03 these replace the scaler constants that used to live in `config.h`.

The model's FULLY_CONNECTED weights must be quantized **per tensor**. This TFLM version has no per-channel FULLY_CONNECTED kernel. It would silently apply the first channel's scale to every channel. The export refuses a per-channel model, and the firmware halts at boot with `FC weights per-channel` if one is flashed.

## Shared settings (`include/config.h`, identical in both stages)

- Pins: PMS5003 on UART1 (RX GPIO18, TX GPIO17), DHT22 on GPIO2, I²C on GPIO8/GPIO9, microSD on CS 10, MOSI 11, SCK 12, MISO 14. GPIO 33 to 37 are taken by the octal PSRAM and must not be used.
- I²C runs in two voltage domains joined by a BSS138 level shifter: ESP32-S3 and INA219 on the 3.3 V side, DS1307 and LCD on the 5 V side. SDA is on shifter channel 3, SCL on channel 2, channel 1 is flaky. The clock is 10 kHz, the rate that worked on the breadboard; try 100 kHz after soldering.
- Humidity correction `pm25 / (1 + alpha * (rh/100)^beta)` ships with `RH_ALPHA = 0`, an exact pass-through, until alpha and beta are fitted against a reference instrument.
- `BENCHMARK_MODE 1` runs the benchmark at boot. The board then keeps answering serial commands, so `bench_capture.py` can repeat it.

## Serial commands (115200 baud, newline-terminated)

| Command | Stage | Effect |
|---|---|---|
| `T=YYYY-MM-DD HH:MM:SS` | both | Sets the DS1307 from the laptop clock and reads it back |
| `F=<id>,pm25,pm10,temp,rh` | 2 | One inference on a raw vector; reply `C=<id>,<class>,<conf>,<latency_us>,<p0>..<p5>`. The sensor cycle pauses while vectors keep arriving |
| `BENCH` | 2 | Latency (cold and warm), RAM and energy protocol; prints `LATENCY`, `RAM`, `ENERGY` lines and `BENCH done` |
| `MODEL` | 2 | `M=<model bytes>,<model crc32>,<input constants crc32>`, the same CRC-32 as Python's `zlib.crc32` |

## Laptop side (`code/08_on_device/` in the main repo)

- `verify_on_device.py` first checks the board's `MODEL` fingerprint against the files on disk. It then streams the run 1 field rows and a public test sample through `F=` and compares every reply with the laptop TensorFlow Lite interpreter. It expects identical classes and bit-identical probabilities. A complete run writes `results/on_device_verification*`; any other run gets a timestamped file and leaves the last complete result alone.
- `bench_capture.py` runs `BENCH` and appends a parsed row, with the model fingerprint, to `results/esp32_benchmark.csv`.
- `tests/` holds the pytest suite. It runs against a pseudo-terminal fake of the firmware whose reply formats come from the C sources, plus the host TFLM bit-exactness test. Run `../../.venv/bin/python -m pytest tests -q` from `code/08_on_device`.

Both scripts open the port raw and exclusively (`esp_serial.py`), because pyserial drops bytes on the CH343 bridge.

## Energy benchmark

The INA219 shunt must be in series with the board's 5 V input: adapter 5 V to VIN+, VIN- to the ESP32 5V pin. The board must run from the adapter, not USB, or the run reports `ENERGY INVALID`. The protocol alternates 25 pairs of 400 ms windows. A busy window runs inferences back to back, an idle window waits. The INA219 averages 128 samples (PGA /2), so each reading covers one window only. Energy per inference is power times the measured inference time:

- **total** is the busy power times the inference time.
- **extra** is the busy-minus-idle power times the inference time.

Both are given at the 5 V input and as 3.3 V-rail equivalents.

## CSV files on the card

- Stage 1 `/aqilog.csv`: `timestamp,pm25_raw,pm10,temp_c,rh_pct,bus_V,current_mA`
- Stage 2 `/aqicls.csv`: `timestamp,pm25_raw,pm25_corr,pm10,temp_c,rh_pct,aqi_class,confidence,latency_ms,bus_V,current_mA`

Stage 2 never appends under a different header. If `/aqicls.csv` has another layout, it writes `/aqicls_1.csv` and so on. Timestamps are `uptime_<s>` whenever the clock has no valid time. Send `T=` from the laptop to set it.
